# Material 3 Expressive design lint checks, and a clean full lint of :AnkiDroid

A new `ExpressiveDesignDetector` in `:lint-rules` adds six error-severity checks for the `com.ichi2.anki.ui.expressive` package: `indication = null`, literal `Color(...)` outside `.theme`, literal words in material3 `Text`, `CircularProgressIndicator`, raw `tween`, and `clickable`/`combinedClickable` without a role. Files that predate the checks are exempted per issue in `lint-release.xml` until F3/F4 migrates them. The eight circular indicators became `LoadingIndicator`, or `CircularWavyProgressIndicator` for Maintenance's determinate progress, and the 69 errors of the first full `lintFullDebug` run are fixed with KTX and Compose-resource rewrites, resource deletions, and reasoned suppressions. The detector matches calls by source name and then resolves them, so value-class-mangled Compose functions are caught.

Watch for: `ExpressiveHardcodedText` only sees literals passed straight to `Text`, so snackbar messages and labels, `contentDescription`, and view-model strings pass lint untranslated (confirmed, e.g. `ExpressiveBrowseViewModel.kt:340`); the circular-progress message, the only text the CLI prints, points determinate uses at `LoadingIndicator` (confirmed); stale-import cleanup now compares the mockable `TimeManager` clock with file mtimes (confirmed, production-neutral).

**Verdict**: APPROVED

## High-level view

The detector builds a handler only for Expressive, non-test files, filters calls by name, then resolves them and matches the declaring package, so a same-named function from elsewhere is ignored. Arguments are found by parameter name through lint's argument mapping, which works against the compiled Compose binaries: the pre-exemption run (`f2d-applint2.log`) reported all six IDs, and the one clickable that passes a role, `MoreScreen.kt:229`, was not flagged.

Its reach is the plan's list and no wider. The text rule covers `Text("…")` and templates or concatenations with letters; strings that reach the screen any other way are invisible to it, which matters because F4's gate is "0 lint violations" and the plan's risk table relies on lint to mitigate the release-blocking localization risk. The progress rule's message names only the indeterminate replacements, and with `explainIssues = false` the explanation that mentions the wavy indicators is never printed.

The `<ignore regexp>` lists match the pre-exemption findings file for file, minus the fixed circular indicators, and the probe shows an unlisted file is still checked. Being whole-file, they also accept new violations in those eight files until each entry is removed, which is the stated F3/F4 plan.

The lint fixes keep production behavior with one intended exception: staged imports now open through `openInputStreamSafe`, which rejects URIs whose path normalizes under `/data` (surfaced as `COPY_FAILED`), as Classic's `ImportUtils` already does. Checked: ExpressiveSettings still `apply()`s; every SyncAttemptStore and import-claim write still `commit()`s with its result checked or returned; `SystemTime.intTimeMS()` is `System.currentTimeMillis()`; no deleted resource is referenced in any source set. `LocalResources.current` in Compose UI 1.11.3 is `LocalContext.current.resources` plus a configuration read (checked in the bytecode), the same instance across configuration changes, so the new `remember` keys in StudyScreen do not rebuild the card WebView holder or the media controller on rotation. `LoadingIndicator` applies indeterminate `progressSemantics` (material3 1.5.0-alpha18 bytecode), so TalkBack still finds the busy state. The one fix that sits badly with its rule is `cleanupStale`, whose cutoff now comes from the mockable clock but is compared with file mtimes; that differs only under test.

User-visible changes are deliberate: the study error heading reads "Can’t continue studying", the Transfer replace button and the Maintenance counter now use Classic's translated strings with the same English text, and the sign-in and forget buttons show a 28 dp morphing indicator instead of a 22 dp ring.

### Where untranslated text still passes lint

(confirmed) `hasLiteralWords` inspects only the `text` argument of material3 `Text`, and only literals, templates, and concatenations.

```kotlin
// ExpressiveBrowseViewModel.kt:340: on no ignore list, lint-clean, English in every locale
text = "${receipt.affectedCount} item(s) updated.",

// BrowseScreen.kt:99-102: stays invisible after Browse leaves the list
snackbarHostState.showSnackbar(
    message = message.text,
    actionLabel = if (message.undoStep != null) "Undo" else null,
)
```

The same holds for `contentDescription = "Back"` (SettingsScreen.kt:88) and `"Add"` (HomeComponents.kt:293), which TalkBack reads: removing those files from the lists in F3/F4 will not surface them. A call-site rule can reach snackbar messages and action labels, content descriptions, click labels, and `if`/elvis branches; view-model strings need either a broader rule or an explicit review item in the DoD.

### Stale-file cutoff on the test clock

(confirmed) `cleanupStale` computes `TimeManager.time.intTimeMS() - STALE_AGE_MILLIS` and deletes owned files whose `lastModified()` is older. Under `RobolectricTest`, `TimeManager` is `MockTime(2020, …)` while staged files carry today's mtime, so the 7-day expiry can never fire in a test; nothing covers it today (no `setLastModified` or `STALE_AGE` in the tests), and a future test has to set mtimes from `TimeManager` to exercise it. The export file name suits `TimeManager`; a comparison with a filesystem timestamp is the case the lint rule does not fit.

### Test coverage

The six detector tests cover literal and template text, named and positional `indication`, value-class stubs for mangled names, the theme exemption, package scoping, test-source exclusion, and `@Suppress`. Not tested: `toggleable`, `triStateToggleable`, and `Modifier.indication`; `combinedClickable` (exercised only by the real-code run, in BrowseScreen and HomeComponents); an Expressive call to a same-named function outside Compose, which the resolved-package check handles; string concatenation.

### The maintenance test failure

```
requestDatabaseCheck → runOperation → syncRefusal(DATABASE_CHECK)
  → syncActivity() = sync.state.value.maintenanceSyncActivity()
  → Checking.isCollectionBlocking → COLLECTION → Terminal(…, SYNC_ACTIVE)
```

`ExpressiveSyncViewModel` starts in `Checking` and leaves it when `gateway.snapshots` delivers the first WorkManager snapshot. The failing test calls `requestDatabaseCheck()` after only `runCurrent()`, which doesn't wait for that snapshot. The refusal won once in a loaded 222-test run, and the test passed alone (`f2c-maint1.log`). The two sibling tests wait with `withTimeout(5_000) { state.first { it !is Checking } }`. The same wait would fix this one, as a follow-up outside this diff. The diff doesn't touch the coordinator, the sync view model, or `ExpressiveHomeActivity`. Its only Home-side change moves custom study out of `HomeScreen.kt`.

# Parent-bound Expressive subdeck creation

Task 5 now binds “Create subdeck” to the selected deck by carrying its typed `DeckId` through `ExpressiveDeckGateway` and resolving the final qualified name inside the serialized collection write. Entered hierarchy separators create deeper descendants beneath that parent rather than redirecting creation elsewhere; root creation still accepts qualified names unchanged, and duplicate detection uses the final destination. The previously approved Task 5 behaviors show no regressions. Watch for: no new P0/P1/P2 concerns were found.

**Prior P2**: CLOSED (**confirmed**)

**Verdict**: APPROVED

## High-level view

The UI submits the selected deck’s `did` separately from the relative name. Parent binding is therefore part of the typed operation rather than editable name text.

`ExpressiveCollection.createDeck()` performs parent lookup, qualification, final-name duplicate detection, and creation within one repository write. A missing parent fails instead of silently creating at root; a null parent preserves root-level qualified-name creation.

Child-inclusive delete and guarded undo, filtered-deck actions, collection/resume/sync refresh, all six Custom Study mappings and session IDs, cancellation propagation, and dedicated normal/filtered options destinations remain on their prior paths.

## Selected-parent identity survives hierarchy separators

`HomeScreen` calls `createDeck(name, parentDid = addDeckParent?.did)` instead of encoding the parent in editable text, and `ExpressiveDeckGateway` carries that parent as `DeckId?`. Inside `ExpressiveCollection`, `decks.getSubdeckName(parent, relativeName)` runs under `repository.write`; the helper prepends the selected parent’s current qualified name to the complete relative input. `Child::Grandchild` therefore becomes `SelectedParent::Child::Grandchild`, and a deleted parent fails the operation instead of changing its destination.

## Root qualification and collision handling use the final name

With a null `parentDid`, the trimmed input is passed through, so root creation accepts both `Deck` and `Deck::Child`. With a parent, qualification happens before the case-insensitive `allNamesAndIds()` check, so duplicate detection covers the actual qualified destination, including nested relative input.

## Task 5 action and lifecycle paths are unchanged by the fix

Delete still previews descendant cards and permits undo only while its captured backend step remains on top. Filtered rows still expose Rebuild and Empty rather than Custom Study and Create subdeck, while direct reloads and collection invalidations refresh Home after mutations.

Custom Study still maps Extend New, Extend Review, Forgotten, Review Ahead, Preview New, and Cram to the backend request and returns `decks.selected()` for session-producing modes. Cancellation is rethrown in load and Custom Study paths, and dialogs remain disabled while work is active.

Normal options still use the backend-owned `DeckOptions` destination, filtered options still use `FilteredDeckOptionsFragment`, and Activity resume/change keys refresh Home when either dedicated surface returns.

# Activity-owned note and card editing for Expressive Home, Browse, and Study

Task 6 routes all Expressive add/edit actions through the backend-backed `NoteEditorActivity`, with one Activity-owned coordinator persisting request ownership across recreation and returning origin-enriched results to the shell. Home supplies the backend-selected deck, Browse carries its saveable query and current card ID, and Study serializes post-editor reconciliation with the review queue while invalidating session-owned undo state. The direct editor route keeps Classic as an explicit fallback rather than an intermediate shell. Watch for: **confirmed P2** — Image Occlusion edits return `RESULT_UPDATED_IO_NOTE` without the standard extras, but the new callback records that result as an unchanged cancellation, leaving Study stale and its undo affordance valid until a guarded undo fails.

**Verdict**: NEEDS_CHANGES

## High-level view

`ExpressiveEditorCoordinatorViewModel` permits one request or unconsumed result at a time, persists both through `SavedStateHandle`, and relies on `ActivityResultRegistry` rather than relaunching an already-dispatched editor after host recreation. The origin survives separately from the Activity result, so Study owns its reconciliation while Home and Browse use the shared collection refresh keys.

The request-to-launcher mapping stays on canonical feature destinations: Home uses `AddNote(selectedDeckId)`, Browse uses `AddNoteFromCardBrowser(query, deckId)` and `EditSelection(cardId)`, and Study uses `AddNoteFromReviewer` and `EditSelection(cardId)`. Classic remains an explicit More-screen fallback rather than an editor host.

Study treats ordinary cancellation as a no-op, refreshes the current card after a non-structural mutation, and reselects the deck before loading after `EXTRA_RELOAD_REQUIRED`. Queue work is mutex-serialized, and any recognized mutation clears the session’s captured review undo tokens before the new card state is exposed.

**Confirmed P2:** the Image Occlusion editor closes `NoteEditorFragment` with result code `11` and no data extras after committing an edited note. The Activity callback only recognizes `RESULT_OK` plus the two booleans, so this committed edit is delivered to Study as `changed=false, reloadRequired=false`.

## Persisted single-owner launch and result delivery

The coordinator stores a versioned request before sending the launch event and rejects another open while either a request is pending or a result is unconsumed. Once dispatch is recorded, restoration waits for `ActivityResultRegistry` to deliver the existing Activity’s result; a request restored before dispatch is emitted once, while malformed serialized state is discarded. Results remain persisted until the relevant origin consumes the request ID, preventing rotation between callback delivery and Compose handling from losing Study reconciliation.

A launch exception clears the pending request and resume suppression. Canceled editor results complete and consume the request without forcing collection refresh; the generic resume invalidation is suppressed for editor returns so cancellation does not masquerade as a mutation, while recognized `changed || reloadRequired` results increment the shared refresh key.

## Canonical Home, Browse, and Study entry points

Home reloads `selectedDeckId` with the deck tree and passes it into `NoteEditorLauncher.AddNote`. Browse keeps its query in saveable state, sends that query through `AddNoteFromCardBrowser`, closes the preview before the external edit surface is shown, and maps a selected row to one-card `EditSelection`. Home, Browse, and Stats are invalidated through the Activity refresh key and collection notifications after recognized mutations.

Study maps both the toolbar/gesture edit action and reviewer add action to the same Activity-owned request path. Its result effect only consumes Study-owned results after `refreshAfterNoteEditor` returns, so cancellation of the effect during recreation leaves the persisted result available for retry. Non-Study results are consumed by the shell rather than entering the retained review session.

## Structural queue rebuild and session-owned undo

`refreshAfterNoteEditor` returns immediately for a true cancellation. A recognized mutation first clears all review tokens captured by this session, then enters the same mutex used by select, reveal, grade, undo, bury, suspend, mark, and flag operations. `reloadRequired` advances the session generation, resets visible progress, reselects the retained deck to rebuild scheduler state, and then loads the current queue card; a plain changed result reloads the current backend card without rebuilding the queue.

Review answers capture the backend undo step in the committing transaction, and undo succeeds only while that step remains the backend’s top operation. Generation checks prevent old work from publishing into a rebuilt session, and failed structural reloads preserve enough state for Retry to reselect the deck.

## Image Occlusion completion is misclassified as cancellation

**Confirmed P2:** `ExpressiveHomeActivity.kt:59-63` derives `changed` only from `resultCode == Activity.RESULT_OK && EXTRA_NOTE_CHANGED` and derives structural reload only from `EXTRA_RELOAD_REQUIRED`. The canonical note editor has a committed edit exit that does not satisfy either condition: after a successful Image Occlusion edit, `NoteEditorFragment` sets `changed = true` and `reloadRequired = true` but calls `closeNoteEditor(RESULT_UPDATED_IO_NOTE, null)`, producing result code `11` with no result `Intent` or extras.

The coordinator therefore persists `changed=false, reloadRequired=false`. In Study, `StudyViewModel.kt:165` treats this as cancellation and skips card refresh, queue rebuild, and immediate undo invalidation; the old rendered card remains visible, and `canUndo` can remain enabled until the backend top-step guard rejects it. The resume fallback cannot repair this because the editor request deliberately suppresses that refresh, and the Activity’s shared refresh key is not consumed by Study. Treat `NoteEditorFragment.RESULT_UPDATED_IO_NOTE` as a committed structural mutation (`changed=true`, `reloadRequired=true`), or normalize that code into the same result contract before calling `editorCoordinator.complete`.

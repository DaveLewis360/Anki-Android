# Task 3 sync gating and navigation contract fixes

Task 3 now holds the Expressive shell in a fail-closed reconciliation state until WorkManager supplies its first snapshot, with collection-backed content and sync actions unavailable during that interval. Navigation intents now read every route they can write, and Study persistence is pinned by an exact version-one wire snapshot in both directions. Activity back handling preserves a hidden Study destination while sync projects More, then pops that durable overlay before allowing the Activity to finish. The four prior findings are closed, and no P0, P1, or P2 regression was found in their fixes.

Watch for: No remaining blocking or non-blocking issue was found within the four requested fix areas.

**Verdict**: APPROVED

## High-level view

Sync startup now uses `Checking` as an active, fail-closed state rather than assuming the collection is available. The shell projects More, removes Home/Browse/Stats from composition, blocks root navigation and external gateways, and ignores sync clicks until the first gateway snapshot transitions the model.

The typed Activity intent contract is symmetric for Home, Browse, Stats, More, Settings, and Study. Saved navigation remains versioned separately, with an exact v1 Study JSON fixture protecting both emitted field shape and backward decoding.

Active sync changes only the rendered destination; the saved stack still retains Study. Activity-level back dispatch therefore removes that hidden durable overlay first, including after saved-state recreation, and only a subsequent back finishes the Activity.

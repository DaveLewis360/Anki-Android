# Native Expressive Browse parity after back and tag fixes

Task 7 adds a native Cards/Notes browser with process-restored search and selection state, debounced and explicitly truncated search, typed bulk operations, repository-backed invalidation, and guarded undo. This pass re-checks the two prior P2 findings and the requested parity surface after their fixes. Mixed tags now have all three final states, and Browse-local back handling now participates only while Browse is the visible unobscured tab. **Watch for:** no remaining actionable P0/P1/P2 behavior issue was found in the scoped Task 7 changes.

**Verdict**: APPROVED

## High-level view

Cards and Notes retain distinct row identities through search, selection, persistence, and mutation normalization. Note rows expand to sibling cards for card-oriented operations, while delete and tags retain note semantics.

Browse restores request and identity state from `SavedStateHandle`, then reloads rendered rows when collection access opens. Debounce cancellation, explicit error/truncation state, and collection-change reconciliation keep results, selection, and preview aligned with the active request.

Bulk operations use one repository write, preserve backend `OpChanges`, and return undo ownership tied to the backend’s exact top step. Sync removes collection-backed tabs from composition; Browse back handling is disabled off-tab and under Settings or Study, and add/edit routes use the dedicated note editor rather than a Classic browser fallback.

## Mixed-tag final states now reach the single note update

The tags dialog makes the mixed-tag set editable instead of resubmitting it unchanged. Leaving a mixed tag in that field retains each note’s state, moving it to selected applies it to all notes, and removing it from both fields removes it from all notes. `editTags` normalizes names case-insensitively, computes changed notes, and sends them through one `updateNotes` write, preserving one backend undo entry and collection event.

## Browse back dispatch is scoped to the visible navigation layer

`ExpressiveApp` enables Browse back handling only when Browse is visible and neither Settings nor Study is active. `BrowseScreen` combines that gate with local state, so hidden always-composed Browse state cannot outrank shell navigation; visible Browse retains dialog → preview → selection ordering before delegating to Activity navigation.

## Typed normalization carries operation parity

`BrowseRowId.Card` and `BrowseRowId.Note` are mode-validated before collection access. Card selections retain card IDs and derive distinct note IDs; note selections retain note IDs and derive every sibling card ID. Delete uses the mode-specific backend overload, tags and mark operate on notes, and reset, due date, reposition, move, flag, suspend, and bury consume normalized card IDs.

Reposition reports unsupported cards and rejects an entirely unsupported selection. Due dates validate ranges and force interval updates under FSRS, moves reject filtered decks, mixed mark/suspend/bury selections converge to enabled, and all-enabled selections toggle off.

## Restored search state is identity-only

The ViewModel persists request, selection, anchor, and preview identities with card/note prefixes, but not rendered rows. Collection access stays closed until Browse is composed, and successful searches intersect restored or stale identities with loaded rows. Query debounce cancellation plus a post-read cancellation check prevents obsolete results from committing; failures remain visible with retry, truncation is explicit, select-all covers the loaded page, and long-press ranges are inclusive.

Each mutation receipt captures `undoStatus.lastStep` only when undo exists, and undo refuses a receipt that is no longer the exact top step. Failed writes retain selection and expose the error rather than publishing a successful mutation state.

# Material 3 Expressive chrome for the Study screen

The Study screen's hand-built chrome is replaced with material3 1.5.0-alpha18 components. The old chrome was a timer strip, a deck row with an "Add note" text button, a seven-icon row, Surface answer tiles, and a "SHOW ANSWER" pill. `StudyLayout` puts a subtitle `TopAppBar` over the wavy progress at the top of a `Scaffold`. At the bottom, a `HorizontalFloatingToolbar` sits above the answer controls: a medium shape-morph Show answer `Button`, or `ButtonGroup` rating rows that wrap 4/2/1 by measured label width. Labels come from resources and TR strings, ratings and marking give haptics, and the card pane no longer squeezes out the type-answer field. API use checks out against the alpha18 AAR, and the test, screenshot, and ktlint runs all postdate the last edit.

**Watch for:** two likely issues, both should-fix:

- The one-row branch keys on height alone. A phone in portrait split-screen (≈411 × 415 dp) therefore stacks the four ratings in a 112 dp column and leaves the card about 70 dp.
- The type-answer field this change makes visible, and Show answer with it, are covered by the keyboard as soon as the field is focused. The edge-to-edge Expressive host applies no IME insets.

Four confirmed nits:

- The flag icon stays full color while the toolbar is disabled.
- The current flag in the menu is a silent checkmark.
- The ellipsized title drops the leaf deck first.
- A failed flag-name lookup leaves an empty menu.

**Verdict**: NEEDS_CHANGES

## High-level view

`StudyLayout` wraps a `Scaffold` in `BoxWithConstraints`. The bottom bar stacks the toolbar over the answer controls at up to 640 dp wide. In windows shorter than 480 dp, it puts both in one row, up to 960 dp wide. Because that switch ignores width, short but narrow windows get a row they can't hold.

Undo and Add note move to the app bar and keep their enabled rules (`!working && canUndo` and `!working`). The title is the full deck path with an end ellipsis. At 2× the phone title reads "French::…" (confirmed in `study_answer_font_2x.png`). When Classic's reviewer shows a title, it uses `Decks.basename`.

The toolbar keeps every removed action, and all of them are disabled while an operation runs. The flag button now opens a menu of `Flag.queryDisplayNames()`, including the no-flag entry, instead of cycling, and it announces the set flag as its state description. The FLAG gesture still cycles, and the key bindings are untouched.

Every answer button is weighted, so alpha18's `ButtonGroup` measure policy hands out exactly the row width and the required overflow menu can never appear. Again gives `Reject` haptics and the other ratings `Confirm`. Gesture grading fires the same haptics, under the same condition as the ViewModel's `grade` guard.

`CardPane` now takes `weight(1f)`, so the type-answer field keeps its height. Nothing in the host handles IME insets, which the field needs to stay visible while the user types.

The component tests cover semantics and the 1×/2× wrap. The row switch, the type-answer layout, the haptics, and flag-name loading have no test. No screenshot uses dynamic color.

1. **Height-only one-row switch** (likely): short, narrow windows such as portrait split-screen stack four ratings in a 112 dp column and leave the card about 70 dp. Require width too (for example `maxWidth >= 600.dp`), or fall back to the column when four ratings don't fit.

3. **Flag icon ignores the disabled state** (confirmed): the `Color.Unspecified` tint keeps the flag full color while the rest of the toolbar dims. Apply the disabled alpha to the colored flag.
4. **Current flag silent in the menu** (confirmed): the current flag has a checkmark only, with no selected semantics. Use alpha18's selectable `DropdownMenuItem(selected = …)`.
5. **Empty flag menu on lookup failure** (confirmed): `runCatching` falls back to `emptyMap()`, which hides every item, and it also swallows cancellation. Fall back to the default names, or report the error.
6. **Leaf deck name ellipsized away** (confirmed at 2×): show the basename as Classic does, or ellipsize the start of the path.
7. **One per row can still cut a label** (confirmed): `count == 1` is accepted unconditionally while the label keeps `maxLines = 1`. Allow two lines there, or soften the KDoc's "never".

### One-row controls in a short, narrow window

**Likely.** The branch condition is `maxHeight < 480.dp`, with no width check. It works for the 914 × 411 dp landscape phone in the screenshots, where the toolbar and four ratings fit in one row. Portrait split-screen on the same phone gives roughly 411 × 415 dp.

The toolbar measures 255 dp in the captures. After the 16 dp side padding and the 12 dp gap, the weighted answer box is 379 − 255 − 12 = 112 dp. At 1× the widest rating plus padding is about 58 dp, so `AnswerButtons` finds that neither 4 per row (256 dp) nor 2 per row (124 dp) fits. It then stacks all four: 4 × 56 + 3 × 8 = 248 dp.

```
~411 × 415 dp window (split screen): maxHeight < 480, so the row branch
┌─────────────────────────────────────────┐
│ ✕ French::Vocabulary   0:12   ↶   ⊞     │  ~82 dp bar + wave
│ card ≈ 70 dp                            │
│ ┌──── toolbar 255 dp ────┐   ┌ Again ┐  │
│ │  ↻   ★   ⚑   ✎   ⋮     │   │ Hard  │  │  248 dp
│ └────────────────────────┘   │ Good  │  │
│                              │ Easy  │  │
└─────────────────────────────────────────┘
```

In the same window, the old column layout left about 165 dp for the card. On the question side, "Show answer" gets the same 112 dp and wraps onto two lines. Two fixes would keep the landscape behavior and cover the narrow case: also require a minimum width, or fall back to the column when the answer box can't hold four ratings. The screenshot matrix doesn't cover this case.

### The type-answer field and the keyboard

**Likely.** The field used to get zero height. It now sits at the bottom of the Scaffold content, directly above the bottom bar. `ExpressiveHomeActivity` calls `enableEdgeToEdge()` and inherits the application-wide `adjustResize`. According to `git grep`, nothing under `ui/expressive` reads `WindowInsets.ime` or calls `imePadding()`.

Under edge-to-edge the window isn't resized for the keyboard. On focus, the IME would cover the field, the toolbar, and Show answer, and the learner would type blind until Done reveals the answer. Adding the IME to the bottom bar's insets lifts the controls, and through the Scaffold padding the field as well:

```kotlin
.windowInsetsPadding(WindowInsets.navigationBars.union(WindowInsets.ime))
```

The missing IME handling predates this diff, but the field fix only helps the user who is typing once it exists.

### Flag menu and toolbar states

**Confirmed.** `FlagIcon` draws set flags with `tint = Color.Unspecified`, while `IconButton` shows the disabled state through `LocalContentColor`. `working` is true during every answer save. During that time the other four icons dim to 38 %, but a red flag stays full red.

**Confirmed.** In the menu, the only marker on the current flag is a checkmark with `contentDescription = null`, and the item has no selected semantics. TalkBack users in the menu can't tell which flag is set; the button's state description helps them only before they open it. Alpha18 already ships a selectable item that sets `Role.RadioButton` and the selected state, and it would replace the manual checkmark:

```kotlin
DropdownMenuItem(
    selected = option == flag,
    onClick = { /* … */ },
    text = { /* … */ },
    shapes = MenuDefaults.itemShape(index, count),
)
```

**Confirmed.** `flagNames` starts as `emptyMap()` and falls back to it on any exception, through a `runCatching` that also swallows cancellation. The menu skips flags that have no name. After a failed lookup, the flag button therefore opens an empty popup for the rest of the session, with no message.

### Answer sizing edge and the Show answer disabled look

**Confirmed.** The `count == 1 ||` guard accepts one rating per row whether or not its label fits. The label keeps `maxLines = 1` with an ellipsis, so a translation wider than the whole row is still cut, though the KDoc says "never".

**Likely.** Show answer uses the default disabled colors while `schedulingReady` is false. On a deck with custom scheduling JS, that is every question until the WebView reports back. The button now flashes from the M3 disabled grey to primary on each card; the old button only dropped to 60 % alpha. The ratings avoid the same flash on purpose by keeping their colors while disabled.

### Test and screenshot coverage

**Confirmed.** `StudyComponentsTest` checks roles, 48 dp heights, spoken labels, enabled and toggle states, flag naming, menu routing, and the 1×/2× row decision against real text layouts with NATIVE graphics.

Not tested:

There is therefore no medium-width tablet-portrait capture, and there is no dynamic-color capture.

# Native Expressive Browse with typed bulk operations

Task 7 replaces the placeholder browser with a native Cards/Notes surface whose search state and typed row identities survive recreation, and routes bulk operations through `CollectionRepository`. Search is debounced and stale-result-safe, selection is reconciled against each loaded page, and note-mode mutations normalize to sibling cards or distinct notes as required by the operation. Two UI-level parity gaps remain in tag final-state editing and back dispatch. **Watch for:** **confirmed P2** mixed tags can never be removed from all selected notes; **confirmed P2** hidden Browse state can consume back presses while another tab or Settings is visible.

**Verdict**: NEEDS_CHANGES

## High-level view

The Browse gateway separates `CardId` and `NoteId`, persists only request and identity state, and derives rendered rows again after recreation or collection invalidation. Bulk card operations normalize note rows to sibling cards, while delete and tag operations retain note semantics; backend `OpChanges` and exact-top undo ownership stay inside repository writes.

Tag editing exposes common tags as editable text but hard-codes every mixed tag as indeterminate on submission. It can preserve or promote a mixed tag, but cannot remove that tag from every selected note.

Browse remains composed to preserve tab state, but its `BackHandler` is enabled solely by Browse-local state. A selection, preview, or dialog left open before changing tabs can therefore outrank shell and Settings back handling even though Browse is no longer visible.

## Mixed tags have no “remove from all” final state

**Confirmed P2.** `TagsDialog` initializes the editable value from only `selection.selectedTags`, describes mixed tags as permanently “kept unchanged,” and always submits the original `selection.indeterminateTags` unchanged (`screens/BrowseScreen.kt:552-592`). The gateway retains an existing tag whenever its normalized key is indeterminate or selected (`ExpressiveCollection.kt:705-739`). Typing a mixed tag into the selected field adds it to missing notes, but there is no UI action that removes it from `indeterminateTags`; deleting text cannot remove that tag from notes that already have it.

Replace the plain common-tag field with tri-state tag controls, or maintain editable `selected` and `indeterminate` sets so each mixed tag can move to selected-for-all, absent-for-all, or retain-per-note before constructing `TagFinalStateRequest`. Keep the single `updateNotes(changedNotes)` write so the final state still produces one backend undo entry and one collection event.

## Always-composed Browse intercepts shell back navigation

**Confirmed P2.** `ExpressiveApp` composes Browse whenever sync is inactive regardless of the selected tab (`ExpressiveApp.kt:113-153`), while `BrowseScreen` enables its back callback whenever a Browse dialog, preview, or selection exists, with no visibility or shell-overlay condition (`screens/BrowseScreen.kt:103-107`). The innermost enabled callback wins, so leaving a Browse selection active, switching to More, opening Settings, and pressing Back clears the hidden Browse selection before closing Settings. The same hidden callback can consume back on Home, Stats, or More instead of delegating directly to the shell.

Pass an `active` flag derived from `visibleTab == 1` and the absence of Settings/Study overlays, and include it in the Browse `BackHandler` predicate. Visible Browse then keeps the required dialog → preview → selection order before delegating to the Activity/navigation shell; hidden Browse does not participate in back dispatch.

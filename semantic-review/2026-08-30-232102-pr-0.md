# Durable AnkiWeb collection, media, and full-sync orchestration

Task 11 moves Expressive sync ownership into a WorkManager collection→media chain, resolves credentials by generation at execution time, and handles backend-directed one-way syncs while reserving ambiguous conflicts for native Keep Local/Keep Remote confirmation. Redirect CAS, forced pre-download backup, the unmetered media constraint, typed non-sensitive worker outputs, and the startup marker are present, but durable ownership and process-death reconciliation are not race-safe. Watch for: **confirmed P1** active sync replacement; **confirmed P1** orphaned or mismatched durable attempt IDs; **confirmed P1** terminal acknowledgement lost across process death; **confirmed P1** username PII in `SavedStateHandle`; **likely P1** reopen-before-abort during cancelled full sync; **confirmed P2** a prohibited new test file.

**Verdict**: NEEDS_CHANGES

## High-level view

The enqueue path uses `REPLACE` and publishes proposed collection/media IDs before WorkManager commits the chain. It therefore neither preserves an existing durable owner nor guarantees that the stored IDs identify accepted work (**confirmed P1**).

Reconciliation observes only the IDs in `SyncAttemptStore`. A missing `WorkInfo` is treated as queued forever, turning the pre-enqueue persistence window into a permanent process-death stall (**confirmed P1**); terminal acknowledgement has a second crash window because saved state is marked before the durable store is updated (**confirmed P1**).

Worker `Data` no longer contains credential material, but the Expressive account form separately writes username into `SavedStateHandle`, violating the explicit no-username persistence boundary (**confirmed P1**).

Cancellation is caught outside full-sync cleanup, so `reopen(afterFullSync = true)` runs before `cancelSync()` aborts the backend. If coroutine cancellation returns before the native operation stops, cleanup races the active full sync (**likely P1**).

Focused full-debug compilation and sync tests pass. The Task 11 ViewModel coverage is in a newly created test file despite the no-new-test-files constraint (**confirmed P2**), and the tests do not cover KEEP rejection, death during enqueue or acknowledgement, or cancellation during one-way sync.

## Unique work replaces the existing durable owner

**Confirmed P1.** `SyncWorker.start()` changed unique collection work from `KEEP` to `REPLACE` at `AnkiDroid/src/main/java/com/ichi2/anki/worker/SyncWorker.kt:378`. A second start from another Activity instance, Classic background autosync, or two racing callers cancels the queued/running collection chain and dependent media work. The first UI still holds those exact IDs and reports cancellation unrelated to user action while the replacement begins against the same collection.

Restore `ExistingWorkPolicy.KEEP`. When KEEP rejects a candidate because unfinished work owns the name, return and observe the accepted chain’s logical attempt and exact IDs.

## Candidate IDs are committed before WorkManager acceptance

**Confirmed P1.** `SyncWorker.start()` writes newly generated IDs to `SyncAttemptStore` at `SyncWorker.kt:363-375`, then begins/enqueues work at `SyncWorker.kt:376-381`. Process death after the preferences commit but before the WorkManager transaction leaves a record whose collection job never existed. On restart, `expressiveSyncSnapshot()` maps `collection == null` to `COLLECTION_QUEUED` at `AnkiDroid/src/main/java/com/ichi2/anki/ui/expressive/ExpressiveSyncViewModel.kt:188`, with no repair path, blocking collection UI indefinitely.

Concurrent starts can also interleave record writes and enqueue transactions until the durable record and actual unique owner describe different attempts. Introduce a durable pending/accepted enqueue protocol, serialize in-process starts, and reconcile against WorkManager after enqueue and at startup. Publish only accepted IDs; repair or clear an unaccepted pending record instead of treating null as queued forever.

## Terminal acknowledgement can be skipped after process death

**Confirmed P1.** `acknowledgeOnce()` writes `KEY_ACKNOWLEDGED_TERMINAL` to `SavedStateHandle` at `ExpressiveSyncViewModel.kt:517-522` before `gateway.acknowledgeTerminal()` commits IDs to `SyncAttemptStore`. Process death between those operations restores the saved-state marker, sees the same terminal WorkInfo, and returns without durable acknowledgement. The terminal attempt remains discoverable on later entry.

Make durable acknowledgement the first idempotent operation and mark saved state only after the exact attempt/collection/media IDs are committed. Prefer deriving acknowledgement from `SyncAttemptStore`; after a committed acknowledgement, process recreation naturally reconciles to IDLE.

## Expressive account input persists username PII

**Confirmed P1.** `ExpressiveAccountViewModel` restores username from `SavedStateHandle` at `AnkiDroid/src/main/java/com/ichi2/anki/ui/expressive/ExpressiveAccountViewModel.kt:109`, writes every edit at line 124, and writes the authenticated username again at line 161. Framework-saved state can be serialized, so an email/username crosses the explicit persistence boundary.

Remove `KEY_USERNAME` saved-state reads/writes and keep unfinished login input in memory only. Display authenticated identity from encrypted `SyncCredentialStore`; leave an interrupted form blank after process recreation.

## Full-sync cancellation reopens before aborting the backend

**Likely P1.** `fullUploadOrDownload()` is wrapped by cleanup that calls `reopen(afterFullSync = true)` at `SyncWorker.kt:186-191`. The only cancellation abort is in the outer `doWork()` catch at `SyncWorker.kt:111-115`, after that `finally`. If cancellation detaches the coroutine before the backend has stopped—the reason `cancelSync()` is explicitly required—reopen can race collection replacement or fail while full sync still owns the collection.

Catch cancellation around close/full-sync, call `cancelSync()` before cleanup, then rethrow while retaining guaranteed reopen. Cover cancellation during full upload and full download, asserting abort-before-reopen and an open collection afterward.

## Task 11 adds a disallowed test source

**Confirmed P2.** `AnkiDroid/src/test/java/com/ichi2/anki/ui/expressive/ExpressiveSyncViewModelTest.kt:33` declares a new, untracked Task 11 test class even though new test files were disallowed. This violates the delivery constraint despite the tests passing.

Move the cases into an existing allowed sync/ViewModel test source or remove the file. Add race/process-death coverage only within permitted existing files.

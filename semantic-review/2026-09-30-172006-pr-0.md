# Anki's words and Material 3 Expressive panes for the Study screen

The Study screen's loading, error, and congratulations panes move out of `StudyScreen.kt` and `HomeScreen.kt` into two new files, together with the timebox and unbury dialogs, the long-press action menu, and custom study. They're restyled as Material 3 Expressive: a cookie-shaped badge grows in on the slow spatial spring, turning on the congratulations pane, above a heading, the messages, and buttons by emphasis. The hard-coded English goes with the move. The congratulations and timebox texts are Anki's TR strings, custom study takes the TR labels Classic uses, gesture names reuse AnkiDroid and TR strings, and the screen resolves the view model's new `StudyMessage` with its own context. Every action and enabling condition of the removed code carries over, and the test, ktlint, and i18n runs postdate the edits they cover. Three things fall short: the congratulations pane drops the second half of Anki's next-learning message, English still reaches users through exception text, and two restyled controls lost the button role or the scrolling the removed ones had.

**Watch for:**

- **Confirmed, medium:** Anki's congratulations page follows "The next learning card will be ready in 5 minutes." with "There are N learning cards due later today." (`scheduling-learn-remaining`). The pane shows only the first sentence, and `ExpressiveCongratulationsInfo` doesn't carry `learnRemaining`.
- **Confirmed, low:** `StudyMessage.of` prefers any exception message over the new app strings. The new custom scheduling "detail" also forwards the app's own English JS error, `The scheduling mutation runtime is unavailable`.
- **Confirmed, low:** the unbury choices no longer announce as buttons, because alpha18's clickable `SegmentedListItem` sets no role.
- **Confirmed, low:** the long-press menu no longer scrolls. `DropdownMenuPopup` adds no scroll of its own, and the flag menu needed exactly this fix in part B.
- **Confirmed, low:** the custom study amount field asks for an unsigned number keyboard where Classic declares a signed one, and it lost its busy label.
- **Likely, low:** the same field puts a content description on an editable node.

**Verdict**: NEEDS_CHANGES

## High-level view

The panes share one scaffold, `StudyPane`, which scrolls when its content doesn't fit. The removed code's behavior carries over intact. Back to decks stays enabled while an operation runs, and the deck actions wait. Unbury, rebuild and empty, and custom study appear under the same conditions as before, and both kinds of buried cards still open the unbury dialog. Three things do change. Back to decks moves from last place to the filled button at the top, the labels are Anki's own, and the timebox minutes round, as in ReviewerFragment and on the desktop, instead of flooring.

The congratulations messages follow the desktop page's selection and order: next learning card, review limit, new limit, buried cards, then the custom study hint. `asParagraph` joins Fluent's wrapped lines, which translations carry too. The desktop's next-learning message has two sentences, though, and the second needs a count the pane doesn't receive.

The timebox dialog matches ReviewerFragment word for word. Upstream marks its two strings obsolete, but more locales translate them than their replacement, so keeping parity is the better choice for now. The unbury dialog keeps the desktop's three modes in the desktop's order, in sentence case, but its choices lost the button role. The gesture menu's items gain the button role, but the grouped popup loses the scroll that `DropdownMenu` provided.

Custom study's mode labels, cram kinds, and availability line match Classic's, and each radio choice is selected by its whole row. The amount field is where the dialog slips. It has a content description on an editable node, and an unsigned keyboard, since the build's Compose 1.11.3 has no signed keyboard type. The desktop prompt no longer tells users that a negative value lowers the limit, and the confirm button no longer changes while the session is created.

`StudyMessage` resolves app strings in the screen's context. The gap is in `of()`: any exception message wins, so only exceptions without a message get the new translated fallback. Backend messages arrive translated, but app and platform exceptions don't.

The new tests pin conditions, actions, roles, and 48 dp targets for the panes and dialogs. They build expected texts from the same TR calls the code makes, so they can't catch a missing sentence. The gesture menu, the cram submission, and the choice of custom scheduling message have no tests.

### Anki's congratulations page, next to the pane

The anki26.05 backend's bundled page (`assets/backend/sveltekit/app/immutable/nodes/5.BgiyFqgX.mjs`) builds the next-learning message as follows:

```js
function Le(l){const a=l.secsUntilNextLearn;if(a>=86400)return"";const e=we(a),h=Math.round(Ce(e,a)),y=xe(e),_=de({amount:h,unit:y}),b=ue({remaining:l.learnRemaining});return`${_} ${b}`}
```

The two calls take the variables of `scheduling-next-learn-due` and `scheduling-learn-remaining`. `congratulationsMessages` makes only the first:

```kotlin
nextLearnDue(info.secsUntilNextLearn)?.let { (unit, amount) -> add(TR.schedulingNextLearnDue(unit = unit, amount = amount)) }
```

The page reads `learnRemaining` from the same `CongratsInfoResponse` that `ExpressiveCollection.congratulationsInfo` maps, and `TR.schedulingLearnRemaining(int)` exists, so the fix is small. The finished-deck test builds its expectation from the single call, so it passes either way. The page also renders the deck's description below the messages. Neither the removed pane nor this one shows it, which leaves a desktop gap for a later slice.

### Where English still gets through

```kotlin
// StudyState.kt
fun of(failure: Throwable?, @StringRes fallback: Int): StudyMessage =
    failure?.message?.let(::Text) ?: Resource(fallback)
```

`launchCatching` in `CoroutineHelpers.kt` treats only the messages of `BackendException` and `InvalidSearchException` as user-facing. `of()` passes every exception's message through, so an `IllegalStateException`, an `IOException`, or a gateway `require` shows as-is. The new fallback strings appear only for exceptions without a message. `loadNextInternal` shows the inconsistency: it still guards with `error("The study session is not initialized")`, a condition that `expressive_study_error_not_started` now words elsewhere. The guard is reachable only before a deck is selected.

The new `state-mutation-error` branch has a reachable case. The injected script reports its own failure on the same channel as the deck's code:

```js
if (!globalThis.anki || typeof globalThis.anki.mutateNextCardStates !== 'function') {
  throw new Error('The scheduling mutation runtime is unavailable');
}
// …
signal('state-mutation-error', String(error && error.message || error));
```

When the reviewer runtime is missing, the snackbar reads "Custom scheduling failed; the usual intervals apply: The scheduling mutation runtime is unavailable". This is app-side English presented as the deck author's detail, whereas `applySchedulingMutation` logs its own app-side failures and shows only the generic message. Two changes would close both paths: restrict `of()` to backend exceptions, and give the runtime check its own signal or no detail. `StudyMessageTest` and `ExpressiveGatewayTest` encode the current precedence and would need updating.

### Custom study's amount field

```kotlin
OutlinedTextField(
    // …
    keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Number),
    modifier = Modifier.fillMaxWidth().semantics { contentDescription = prompt },
)
```

Android's accessibility checks (ATF's `EditableContentDescCheck`) flag a content description on an editable item, because a screen reader may read the description in place of the value. Here the description also repeats the prompt `Text` directly above, so TalkBack reads the prompt twice. The field's `label` slot names the field without either problem. The amount test finds the field by content description and would need to change too.

Classic declares the field signed for the two limit modes:

```kotlin
// a user may enter a negative value when extending limits
if (contextMenuOption == EXTEND_NEW || contextMenuOption == EXTEND_REV) {
    inputType = EditorInfo.TYPE_CLASS_NUMBER or EditorInfo.TYPE_NUMBER_FLAG_SIGNED
}
```

The build resolves Compose foundation 1.11.3, whose `KeyboardType` has no signed variant; its `EditorInfo` mapping never emits `TYPE_NUMBER_FLAG_SIGNED`. `KeyboardType.NumberSigned` arrives in 1.13. The field accepts "-", but whether the keyboard offers the key depends on the IME, which wasn't checked on a device. The removed dialog used the text keyboard. Classic also says so in its prompt, "Increase/decrease (“-3”) today’s new card limit by", while the desktop's TR prompt says only "Increase today's new card limit by".

The confirm button used to read "Working…" while the session was created. Now it stays "OK", disabled like Cancel, and nothing else shows progress.

### Timebox wording and the obsolete pair

The bundled English Fluent file lists `studying-card-studied-in` and `studying-minute` under `## OBSOLETE; you do not need to translate this`. Their replacement is `studying-card-studied-in-minute`, which selects on both counts within one sentence. Joining the old pair gives uneven results in some locales: the Romanian fragment ends with a space, so the join doubles it, and the Malay pair ends without a period. Still, about 54 bundles translate the old pair against 29 for the new string, so switching now would put more locales into English. When upstream drops the pair, the TR methods disappear and the build fails loudly, in both reviewers at once.

The dialog's KDoc says "As in Classic, only the buttons close it". Classic's `Reviewer` builds the timebox dialog with `cancelable(true)`; it's `ReviewerFragment` that calls `setCancelable(false)`.

# Scrollable flag menu for short windows, and a test for the lone-rating wrap

This pass fixes the should-fix from the previous review. The flag menu's `DropdownMenuGroup` now takes `Modifier.verticalScroll(rememberScrollState())`. At large font sizes in a landscape or split-screen phone window, the eight flags scroll instead of running off the window. A component test at 914 × 411 dp and 2× font failed on the missing scroll container before the fix and passes after it. A new landscape 2× capture, light and dark, shows the menu filling the window's height with Turquoise cut at the bottom. A second new test covers a lone rating whose label wraps (previous item 7). The landscape type-answer squeeze stays with the G1 device check, as agreed.

**Verdict**: APPROVED

## High-level view

The modifier lands where alpha18 needs it. `DropdownMenuGroup` applies its `modifier` to the item column inside its shaped `Surface`, so that column scrolls, clipped to the group's corners. `DropdownMenuPopupContent` gives the group no height of its own. The `Popup` bounds it to the window, as the landscape capture shows.

The red run proves only that the scroll container was missing, because `performScrollTo` fails without one even when the target is already visible. The capture, at the same window height and font scale, shows that Purple starts below the window's edge, so the green run does scroll to it. All the evidence postdates the last source edit. The only later edit wraps one chained call in the test, and ktlint and the test class ran again after it.

### The flag group's scroll in alpha18

```kotlin
// alpha18 Menu.kt
fun DropdownMenuGroup(shapes: MenuGroupShapes, modifier: Modifier = Modifier, /* … */) {
    Surface(modifier = Modifier.hoverable(interactionSource), shape = groupShape, /* … */) {
        Column(modifier = modifier.padding(contentPadding), content = content)
    }
}

internal fun DropdownMenuPopupContent(modifier: Modifier, /* … */) {
    Column(modifier = modifier.width(IntrinsicSize.Max).graphicsLayer { /* … */ }, content = content)
}
```

The flag group is the popup column's only child, so it gets the window's full height and scrolls by the menu's excess over it. The popup's `width(IntrinsicSize.Max)` still measures through the scroll: `DropdownMenuContent`, which backs `DropdownMenu`, pairs the two the same way. The portrait capture still sizes the menu to Turquoise, with Red selected, and the radio-semantics test still passes.

The popup keeps the default `Below` anchor. When the menu doesn't fit 48 dp inside both window edges, its last vertical candidate, `bottomToWindowBottom`, centers it (`WindowAlignmentMarginPosition.Vertical` in `MenuPosition.kt`). That places a window-high menu at y = 0, as in `study_flag_menu_land_font_2x.png`.

# Saved-state navigation and sync-time More projection

Task 3 replaces local Compose navigation state with an Activity-scoped, typed back stack persisted as a versioned `SavedStateHandle` snapshot. Root selection replaces the stack, Settings and Study occupy a single overlay slot, and active sync projects More without rewriting the durable destination. Process-death precedence and typed Study restoration are covered, but the sync gate is fail-open while WorkManager state is being discovered, the Settings intent route does not round-trip, and the stable wire schema is not pinned by tests. **Watch for:** **P1, likely** restored collection screens can start before an already-running sync is observed and Study work can outlive composition; **P2, confirmed** `putInitialDestination(Settings)` decodes as Home; **P2, confirmed** route IDs/version and system-back/sync lifecycle behavior lack regression coverage.

**Verdict**: NEEDS_CHANGES

## High-level view

The navigation model enforces one root plus at most one overlay, with saved state taking precedence over a repeated initial intent. Invalid versions, malformed Study arguments, and invalid stack shapes fail closed to Home.

**P1, likely:** composition is gated only by the currently collected sync state. Because that state begins as Idle and active WorkManager state arrives asynchronously, launch or process recreation can start collection-backed tabs or restored Study before More becomes effective; removing Study afterward does not stop its Activity-scoped ViewModel work.

**P2, confirmed:** the intent writer and reader disagree for Settings. **P2, confirmed:** the tests exercise restoration and pure projection but do not freeze the wire representation or execute system-back and active-sync recreation paths.

## Sync discovery can start collection work before the More projection

**P1, likely:** `ExpressiveHomeActivity` collects the sync state and passes it into the shell (`ExpressiveHomeActivity.kt:93-96`, `ExpressiveHomeActivity.kt:135-144`). `ExpressiveApp` treats every non-active value as permission to compose all collection-backed tabs (`ExpressiveApp.kt:66-72`, `ExpressiveApp.kt:95-129`) and a restored Study overlay (`ExpressiveApp.kt:164-174`). Since the sync ViewModel starts at Idle and discovers existing WorkManager work asynchronously, recreating with a running sync and saved Study route can start `StudyScreen` deck loading before the active snapshot projects More.

`StudyScreen`'s deck load runs in an Activity-owned `StudyViewModel`; its `viewModelScope` operation survives removal of the composable. A related ordering window exists for a newly enqueued sync because worker start and Compose disposal are independently scheduled after Queued is published. The gate needs a “sync status unresolved” state that blocks collection consumers and explicit quiescence/start ordering, while preserving the existing Study Mutex, `NonCancellable` grade completion, and undo-token semantics.

No scoped test recreates the Activity with both a saved Study route and active sync, or asserts zero collection-gateway calls before/while More is projected. The pure assertion at `ExpressiveNavigationTest.kt:94-113` cannot expose this lifecycle race.

## Settings is writable but unreadable in the initial-intent contract

**P2, confirmed:** `putInitialDestination()` accepts every destination and writes the codec's route ID (`ExpressiveNavigation.kt:190-204`), including `expressive/settings/v1` (`ExpressiveNavigation.kt:229-238`). `initialDestination()` has no `SETTINGS_ID` branch (`ExpressiveNavigation.kt:170-188`), so `initialDestination(putInitialDestination(Intent(), Settings))` returns Home even though `ExpressiveBackStack.initial(Settings)` supports `[Home, Settings]` (`ExpressiveNavigation.kt:56-64`). Decode Settings symmetrically or reject it at the writer/API boundary.

The Activity test covers only a Study intent (`ExpressiveHomeActivityNavigationTest.kt:18-27`).

## Stable route IDs and lifecycle back behavior are not contract tests

**P2, confirmed:** round-trip tests feed encoder output back through the same codec (`ExpressiveNavigationTest.kt:13-36`), allowing route IDs or the current version to change together without failure. The malformed-input test also resolves both unknown routes and malformed arguments to Home (`ExpressiveNavigationTest.kt:76-89`), so it does not pin the schema. Add a golden assertion over the raw `SavedStateHandle` value for version 1 IDs and Study's `args` shape.

`pop()` return values are tested (`ExpressiveNavigationTest.kt:38-52`), but the Activity test only checks saved-state precedence (`ExpressiveHomeActivityNavigationTest.kt:17-69`). It never dispatches system back to prove overlay pop versus root Activity finish, and no Compose-level test verifies active-sync More projection, durable-stack preservation, and collection-UI suppression together.

# Native Expressive reviewer with repository-backed study state

Task 8 builds the review loop directly in Compose and a restricted WebView, with scheduler reads and writes routed through `ExpressiveStudyGateway` and `CollectionRepository`. It reconstructs rendered state from backend card identity, guards undo against the backend’s current top step, and adds native media, lifecycle, gesture, keyboard, gamepad, and joystick handling without entering the Classic reviewer. Collection-event ownership, gesture recognition, media lifecycle ordering, and timer restoration still have behavioral races. **Watch for:** **confirmed P1** unrelated Expressive writes can be mistaken for the reviewer’s own change; **confirmed P1** suppressed or delayed taps can trigger a different gesture action; **likely P1** fast DOM controls can race interactive-target detection; **confirmed P2** rapid pause/resume can leave media disabled; **confirmed P2** question-side process restore discards the saved timer; **confirmed P2** stale-session invalidation does not stop current media until reload.

**Verdict**: NEEDS_CHANGES

## High-level view

The gateway keeps scheduler mutation under `CollectionRepository`, and answer receipts capture the backend undo step in the same write that commits the grade. Self-change suppression instead treats every event initiated by the singleton `ExpressiveCollection` as local during a timing grace window, so a concurrent Expressive write can be dropped as **confirmed P1**.

Rendering uses a synthetic HTTPS origin, restricted WebView settings, render identities containing card, side, renderer generation, and HTML, plus strict tokens for media commands. Token-aware page completion and media preparation bind side effects to the current render.

Gesture observation preserves WebView scrolling, but recognition state crosses ownership and card-side boundaries. A blocked interactive tap still seeds double-tap state (**confirmed P1**), a delayed single tap resolves against the later reviewer side (**confirmed P1**), and asynchronous DOM hit testing can finish after a fast control tap is released (**likely P1**).

Independent media enable/disable coroutines can finish out of order after rapid pause/resume (**confirmed P2**), and external invalidation leaves old media playing until delayed reload (**confirmed P2**). The timer pauses with lifecycle, but same-card question reconstruction resets its persisted elapsed value (**confirmed P2**).

<details><summary>Details</summary>

## Reviewer change ownership is a singleton-wide timing heuristic

**Confirmed P1.** Reviewer and non-reviewer methods in `ExpressiveCollection` all call `repository.write(initiator = ExpressiveCollection)`. `StudyViewModel.beginWorking()` increments `expressiveOperationGrace`, and `onCollectionChange()` discards any relevant event with that singleton initiator while the counter is positive:

```kotlin
if (attached && change.initiator === ExpressiveCollection && expressiveOperationGrace > 0) return
```

`ChangeManager` queues flow delivery separately from the repository write, so `finishWorking()` calling `yield()` is a delivery-timing guess, not operation correlation. An Expressive mutation delivered while answer, select, flag, mark, undo, bury, or suspend owns the window can leave a stale queue, rendered note, mark/flag state, or undo history. Use a reviewer-session initiator token or correlate the exact admitted write, and test a second Expressive write arriving before the reviewer event is collected.

## Interactive taps can enter card gesture state

**Confirmed P1.** At pointer-up, `CardGestureArea` records `firstTapUpMillis`/`firstTapPosition` and starts a pending job even when `shouldHandleGesture()` returned false. A nearby valid tap within 300 ms then sees active first-tap state and invokes `onDoubleTap()` based only on the second touch, so tapping a link/control and then the card can run a rating or destructive double-tap binding. Rejected touches must not update tap history or create pending work.

**Likely P1.** WebView controls reported as `UNKNOWN_TYPE` begin unblocked while `elementFromPoint(...).closest(...)` resolves asynchronously. ACTION_UP can reach `CardGestureArea` before the callback marks a button, media element, `[onclick]`, or role-based control as blocked, allowing the DOM action and card gesture to both run. Add unresolved ownership or defer gesture commitment, with a callback-after-ACTION_UP contract.

## Delayed single taps resolve against the wrong card side

**Confirmed P1.** `StudyScreen` always supplies `onDoubleTap`, so single taps wait 300 ms. The pending callback then checks the current `StudyUiState` to choose `gestureTapQuestion` or `gestureTapAnswer`; if keyboard input, card JavaScript, or another action reveals/advances first, the original touch runs against a different side or card. Snapshot the selected action and render identity at pointer-up, and cancel pending taps on phase/render changes.

## Pause/resume media enablement can complete out of order

**Confirmed P2.** `ExpressiveReviewerMediaController.setEnabled()` launches an independent coroutine for every lifecycle event. `CardMediaPlayer.setEnabled(false)` suspends while stopping playback before assigning `false`; a newer resume can assign `true` first, then the older pause resumes and overwrites it. Serialize lifecycle requests, cancel/join the previous job, or collect a latest-win enabled state; test pause-during-playback followed immediately by resume.

## Same-card question restore resets persisted elapsed time

**Confirmed P2.** `_seconds` initializes from `SavedStateHandle`, but `loadNextInternal()` writes zero on every non-answered path. During process recreation the same backend card with `KEY_ANSWERED == false` therefore loses `KEY_SECONDS`; the same reset occurs on a same-card foreign refresh. Preserve elapsed time whenever restored identity matches, and reset only for a different card or new session.

## External invalidation keeps stale media alive through debounce

**Confirmed P2.** `onCollectionChange()` invalidates undo and schedules reload after `EXTERNAL_REFRESH_DEBOUNCE_MS` but does not call `requestMediaStop()`. Audio/TTS can continue through debounce and any `operationMutex` wait after the rendered card was edited, deleted, moved, or replaced. Stop media when the foreign invalidation is accepted, before reload coalescing.

## Identity reconstruction and exact-top undo

Answered-side restoration compares persisted card identity with the backend’s current top card before rebuilding the back, avoiding restoration of an already-graded card. `answer()` captures `undoStatus.lastStep` in the answer write, while `undoReview()` refuses backend undo when that step is no longer top; queue objects, rendered HTML, and undo tokens are not persisted.

# Activity-owned editor integration across Expressive Home, Browse, and Study

Task 6 routes Expressive note creation and card editing directly into the backend-backed note editor while retaining request ownership across activity recreation. The coordinator persists one pending request and one origin-enriched result, the activity maps requests to canonical launchers, and each originating surface refreshes at the appropriate scope. The previous Image Occlusion P2 is **confirmed closed**: `RESULT_UPDATED_IO_NOTE` now normalizes to both mutation and structural-reload flags even when the result has no extras. Watch for: no remaining P0/P1/P2 in the scoped editor integration; focused compile, style, note-editor, and navigation validations are reported passing.

**Verdict**: APPROVED

## High-level view

The Activity-owned coordinator persists a request before dispatch and records whether launch crossed the Activity Result boundary. Restoration does not relaunch an already-dispatched editor, while an undispatched persisted request remains recoverable; pending requests and unconsumed results cannot be replaced.

Home, Browse, and Study use their canonical `NoteEditorLauncher` variants. Cancellation completes without refresh, ordinary saves refresh collection consumers, and structural results additionally rebuild the active Study scheduler queue.

Image Occlusion’s nonstandard result code now produces the shared Home/Browse refresh signal and preserves `reloadRequired=true` for Study. Study invalidates undo and reloads the queue within the serialized review-operation boundary.

## Persisted dispatch ownership prevents recreation duplicates

`ExpressiveEditorCoordinatorViewModel` writes a versioned pending request before emitting its launch. Dispatch is recorded immediately after the synchronous Activity Result launch call on the activity’s main collector, so recreation cannot interleave between successful dispatch and persistence. A restored dispatched request waits for `ActivityResultRegistry`; a restored undispatched request emits once so pre-launch process loss does not strand it.

The result retains its persisted origin and request ID until the owning Compose path acknowledges that ID. Malformed pending state fails closed, and a launch failure clears both the request and resume suppression.

## Image Occlusion now follows the structural mutation path

The Activity Result callback checks `NoteEditorFragment.RESULT_UPDATED_IO_NOTE` independently of `Activity.RESULT_OK` and result extras. It therefore calls `complete(changed=true, reloadRequired=true)` when `data` is null, closing the exact gap from the previous review.

For Study, `StudyScreen` forwards both flags before consuming the result. `StudyViewModel` invalidates session undo, advances the structural generation, reselects the retained deck, and loads the scheduler card under `operationMutex`. For Home and Browse, the activity increments the shared collection refresh key; Home reloads its deck state and Browse repeats its saved query.

## Save, cancellation, and origin consumption remain distinct

Standard saves use `RESULT_OK` plus `EXTRA_NOTE_CHANGED`, with `EXTRA_RELOAD_REQUIRED` independently honored. Cancellation completes with both flags false and does not refresh; resume suppression prevents the editor return from masquerading as an external mutation.

The shell consumes Home/Browse results after the activity has emitted their refresh signal. A Study result stays pending until `refreshAfterNoteEditor` finishes, so recreation cancellation leaves it available for another reconciliation pass.

## Canonical launchers preserve feature inputs

Home uses `NoteEditorLauncher.AddNote(deckId)` with its selected deck. Browse uses `AddNoteFromCardBrowser(searchTerms, deckId)` for its saveable query and one-card `EditSelection` for row edits, closing the preview before dispatch. Study uses `AddNoteFromReviewer(FADE)` and `EditSelection(FADE)` rather than routing through the Classic shell.

## Study reconciliation shares review serialization

`refreshAfterNoteEditor` shares `operationMutex` with deck selection and review mutations. Structural edits advance `sessionGeneration` before deck selection, preventing prior-queue work from publishing stale state; nonstructural edits reload the backend card without rebuilding the scheduler. A failed structural reload marks Retry to reselect the deck before the result is consumed.

Earlier full targeted application and libanki suites also passed. The parity ledger leaves this integration as implemented but pending a focused contract.

It resolves all nine findings from the earlier review, including the two subsequent blockers around redelivery-stable identities and partial-close recovery. ## High-level view

Export behavior is gated by one policy used by both coordinator and gateway: only whole-collection scope can produce COLPKG, while deck and note/card selections default to APKG and retain exact backend limits. Restored malformed scope/format combinations decode closed rather than allowing labels and exported content to diverge.

Provider input staging and Create Document output copying are retained coordinator operations with explicit copying states. Saved snapshots contain versioned typed metadata and opaque basenames rather than provider names, URIs, or paths, and every file operation resolves beneath canonical app-owned roots.

External VIEW/SEND imports receive a deterministic SHA-256/base64url identity over length-delimited action, MIME type, and the single source URI. IntentHandler creates it once, DeckPicker and Home preserve it, and Home atomically claims it in a bounded private preference ledger before staging, so independent activity owners cannot admit the same delivery.

Whole-collection replacement uses a strict close/replace/reopen protocol under the collection queue. Partial-close and backend failures preserve their primary failure while attempting recovery, committed reopen failure has a dedicated type, and the gateway invalidates exactly once for both normal commit and committed recovery failure before the coordinator publishes a typed terminal outcome.

## Retained transfer states remove Activity-result ownership gaps

Activity Result callbacks hand request-bound data to `ExpressiveTransferCoordinatorViewModel`, which enters `CopyingImport` or `SavingExport` before I/O in `viewModelScope`. Destination URIs remain coroutine arguments only, interrupted save restores the retained source as retryable `Ready`, stale results are request-ID gated, and successful provider copy persists terminal success before source deletion.

Snapshot encoding omits display names and absolute paths. Opaque tokens are length- and character-bounded, canonical resolvers reject traversal, absolute names, and symlinks, and cleanup is restricted to validated files below import, export, and selection roots. Failed or cancelled staging deletes partial output, while stale cleanup is bounded and excludes active artifacts.

## Durable external identity closes the redelivery window

`ExpressiveExternalImportRequests.identityFor()` hashes a length-delimited tuple of protocol version, action, normalized MIME type, and exactly one URI. Only the bounded digest travels through bootstrap and Home intents; the source URI is not stored in `SavedStateHandle` or the claim ledger.

The synchronized preference claim commits before coordinator state advances to staging. The per-request saved-state list protects recreation, while the application-private claim ledger arbitrates independently created Home owners; restored active, interrupted, or terminal state cannot be overwritten by a redelivery or late picker/page result.

## Replacement commit, recovery, and invalidation remain one boundary

`runStrictCollectionReplacementProtocol()` checks closed state after every close/replace outcome and reopens after a close-then-throw or backend failure. Reopen errors are suppressed onto an existing primary failure; if replacement committed first, reopen failure becomes `CollectionReplacementRecoveryException` so committed data is not mistaken for a pre-commit import failure.

`runCommittedCollectionReplacement()` invalidates after normal commit and after the dedicated committed-recovery exception, then maps the latter to `COLLECTION_RECOVERY_FAILED`. The coordinator keeps replacement, invalidation, source disposition, and terminal publication non-cancellable after admission, so post-commit cancellation cannot produce a false failure or leave subscribers on stale collection state.

The full-collection export protocol observes close/backend/cancellation failure before attempting reopen and preserves both primary and recovery failures. Focused tests cover strict close, partial close, backend and reopen suppression, committed reopen failure, exact invalidation count, typed terminal state, and post-commit cancellation.

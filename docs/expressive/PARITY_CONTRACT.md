# Expressive parity contract

This ledger is the executable boundary between Classic AnkiDroid behavior and the standalone Expressive client. A row is **covered** only when the named contract test exercises it against the real test collection or directly verifies the invalidation rule. Implemented behavior without a focused contract remains **implemented, pending contract**.

## Collection boundary

- All collection access goes through `CollectionRepository.read()` or `CollectionRepository.write()`.
- Both callbacks are non-suspending and inherit `CollectionManager.withCol()` serialization.
- A successful write returns `CollectionWriteResult(value, changes)`: domain values such as `Int`, `Boolean`, IDs, and undo tokens can never be interpreted as change payloads.
- Only normalized `OpChanges` reaches `ChangeManager` and `SharedFlow<CollectionChange>`.
- Reads and failed writes emit no change. Each admitted write completes its commit/result/event boundary under `NonCancellable` and emits exactly one typed invalidation.
- The flow has no replay: it invalidates active consumers and is not durable collection state. Active collectors receive events losslessly through the serialized publisher queue.

## Account and credential boundary

## Deck options parity boundary

Normal deck options deliberately use Anki's backend-owned `deck-options/{deckId}` page through the dedicated `DeckOptions` feature Activity. This is not a handoff to the Classic deck picker: it preserves the version-matched raw `getDeckConfigsForUpdate`/`updateDeckConfigs` protobuf contract, preset and FSRS fields, backend progress, undo, and unsaved-change confirmation without approximating externally generated request fields in Compose. Filtered decks use the dedicated native `FilteredDeckOptionsFragment`/`FilteredDeckOptionsViewModel` contract for searches, limits, ordering, rescheduling, preview delays, allow-empty, and rebuild. Returning from either feature invalidates Expressive Home through `ChangeManager` and the Activity resume key.

These dedicated feature surfaces remain migration targets for Task 17's final Classic-code removal, but neither route opens the Classic runtime shell.

Nothing enters `DeckPicker`, `EmptyCardsDialogFragment`, `MediaCheckFragment`, or `DatabaseErrorDialog`.

## Expansion rule

Every new Expressive collection capability must add or update a row with its Classic source, typed gateway/repository method, read/write classification, expected `OpChanges` flags, consumer invalidation behavior, and focused contract test before its status becomes **covered**.
